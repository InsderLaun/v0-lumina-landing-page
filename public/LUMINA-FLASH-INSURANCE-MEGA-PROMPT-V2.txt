════════════════════════════════════════
2.2 — Routing en /quote y /purchase
════════════════════════════════════════

Cuando llega un request con productId "FLASH-BTC" o "FLASH-ETH",
la API debe:

1. Leer durationSeconds del body
2. Buscar en el array durations[] la entrada que matchea
3. Usar el internalProductId y pBase de esa entrada para calcular la prima
4. Usar el shield address de esa entrada para el CoverRouter

```javascript
// En el handler de /quote y /purchase:
function resolveFlashProduct(productId, durationSeconds) {
  const product = products.find(p => p.id === productId);
  if (!product || !product.durations) return null;
  
  const duration = product.durations.find(d => d.seconds === durationSeconds);
  if (!duration) {
    return { error: "INVALID_DURATION", 
             message: `Flash ${productId} only accepts: ${product.durations.map(d => d.label).join(' or ')}` };
  }
  
  return {
    ...product,
    pBase: duration.pBase,
    shield: duration.shield,
    productId: duration.internalProductId,
    minDuration: duration.seconds,
    maxDuration: duration.seconds,
    trigger: duration.trigger
  };
}
```

Validaciones especiales para Flash:
- durationSeconds DEBE ser exactamente 86400 o 172800
  → Si mandan otro valor: "Flash products accept 86400 (24h) or 172800 (48h) only"
- asset: "BTC" para FLASH-BTC, "ETH" para FLASH-ETH
- No hay stablecoin field

Architecture

How a policy is purchased

The human, through their AI agent, defines coverage parameters. The agent queries the API for a quote based on the kink utilization model, then executes the on-chain transaction through CoverRouter. Collateral is locked 1:1 in the vault. If the trigger fires, payout is automatic; if the policy expires clean, collateral returns to the vault.

Human → AI Agent → Lumina API → CoverRouter → Shield → PolicyManager → Vault locks 1:1

Pricing — Kink utilization model

Inspired by Aave/Compound rate models. Below 80% utilization the multiplier grows linearly; above 80% it grows aggressively. At 95% the policy is rejected to protect LPs from overexposure.

Oracle

EIP-712 signed proofs

Every claim is settled against an EIP-712 typed-data proof signed by the relayer over Chainlink spot data. The domain is fixed to chainId 8453 + verifyingContract — replays across chains or contracts are impossible.

  • LuminaOracleV2 — Ownable, NOT upgradeable. Replacement requires new deploy.
  • Sequencer check — 1h grace period for Base L2 downtime.
  • Staleness — 1,200s for ETH/BTC, 86,400s for stables.
  • MAX_PROOF_AGE — 30 minutes per proof.
Governance & Security

Layered defenses

Core contracts run UUPS proxies under a 48h TimelockController, controlled by a Gnosis Safe 2-of-3. The oracle and Phala verifier are immutable.

  • Solidity 0.8.20 — Native overflow checking.
  • CEI pattern + ReentrancyGuard on every fund movement.
  • 119 tests — Unit + integration.
  • Circuit breakers — maxPayoutsPerDay, large payout delays.
